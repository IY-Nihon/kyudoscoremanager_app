## ⚠️ src/ の構造について（重要）

**`src/` はソースマップから復元されたコードです。** 元の TypeScript ソースは失われており、
現在のファイルは Metro バンドルを展開して復元したものです。そのため:

- ファイル名が `JP_RecordScreen_593.js` のように **モジュールID付き** になっています
- 中身の多くは **minify されたまま**（変数名が `e`, `t`, `n` 等）です
- 展開されていた npm ライブラリは npm パッケージへ戻し済みです。1行転送するだけの
  中継ファイルも削除し、`require('firebase/firestore')` のように直接呼んでいます

現在の `src/` は **91ファイル**で、内訳は以下の通りです。

| 区分 | 件数 | 容量 |
|---|---|---|
| 自作コード | 75 | 1,587KB |
| ライブラリブリッジ | 16 | 10KB |

かつては npm パッケージを1行転送するだけのファイルが20個あり、`require('./module_188')`
のように**番号で**呼んでいました。react を使うのに `module_37` → `module_38` → `react` と
二段辿るものもありました。中身は1行の転送しかないため、呼び出し側を本当の名前へ直して
すべて削除しています。

残る16件は react-native の部品ごとの橋渡しで、`View.js` `Text.js` のように部品名を
そのまま名前にしています。`Text` `TextInput` `StyleSheet` の3件はダークモードの既定色を
ここで当てているため、単なる転送ではありません。

### NativeWind ランタイムの除去について

`src/themedJsx.js`（全画面の JSX が経由するランタイム）の実体は
**react-native-css-interop = NativeWind のランタイム**でした。しかし

- `package.json` に nativewind / react-native-css-interop / tailwindcss が無い
- `babel.config.js` にもプリセットが無い
- 自作コードでの `className` 使用が 0 件
- interop 本体も no-op（`maybeHijackSafeAreaProvider` は恒等関数、
  `interopComponents` が空のため要素差し替えも発生しない）

という状態で、全 JSX 呼び出しに挟まるだけの死荷重になっていたため、
`react/jsx-runtime` へ置き換えました（19ファイル削減）。

## デプロイ

### 順序（守ること）

**アプリを先、決まりを後**に出します。

```bash
npm run deploy:web
```
```bash
npm run deploy:rules
```

順序に理由があります。ライブは団体IDの枝から、団体ごとの推測できない
合言葉の枝へ移りました（`src/liveSecret.js`）。新しい決まりは短い枝を
拒みます。

- 決まりを先に出すと、まだ古い画面を開いたままの人は `live_sessions/{団体ID}`
  へ書こうとして拒まれ、画面を開き直すまでライブが使えません。
- アプリを先に出すと、新しい画面は合言葉の枝へ書きます。古い決まりは枝の
  名前を選ばないので、そのまま通ります。あとから決まりを出せば、穴だけが
  閉じます。

アプリを先に出すと、決まりを出すまでのあいだ、新しい根（`live_limits`・
`live_presence`・`live_view`）への書き込みが拒まれます。**共有リンクを作る
操作が失敗し、接続台数も出ません**。ライブ記録そのものは動きます
（`live_sessions` と `live_history` は古い決まりにもあり、枝の名前を選ばない
ため）。2つのコマンドを続けて叩けば、この窓は1分ほどです。

どちらの順でも、**出した瞬間に行われているライブは切れます**。枝が変わり、
主催者と参加者が別の場所を見るためです。お知らせにもその旨を入れてあります。
練習時間帯は避けてください。

決まりを出したあと、古い形の枝を片付けます。決まりが拒むようになるため、
アプリからは読むことも消すこともできなくなり、放っておくと的中・氏名・
立ち順が残り続けます。

```bash
npm run ops:prune-live
```
```bash
npm run ops:prune-live:run
```

1つ目は下見（何も消しません）。2つ目で実際に消します。

`deploy:rules` は RTDB と Firestore のルールの両方を出します。

### 戻し方（配信で問題が出たとき）

慌てて手で直すと、アプリと決まりの組み合わせが増えて何が動いているのか
分からなくなります。**アプリと決まりは、出した順の逆に戻します。**

**1. まず何が起きているかを読む。** 決まりが原因か、アプリが原因かで戻す先が違います。

```bash
npm run ops:check
```

**2. 決まりを戻す。** 前の版は git にあります。出し直すだけで戻ります。

```bash
git stash && npm run deploy:rules && git stash pop
```

決まりだけを戻すと、**新しいアプリは新しい根（`live_limits`・`live_presence`・
`live_view`）へ書けなくなります**。共有リンクを作る操作が失敗し、接続台数も
出なくなりますが、ライブ記録そのものは動きます。

**3. アプリを戻す。** Firebase Hosting は前の版を持っています。コンソールの
Hosting → リリース履歴から「ロールバック」を押すのが確実で、こちらの手元の
状態に左右されません。手元から出し直すなら、戻したい commit を取り出してから
`npm run deploy:web` です。

**戻す順は「決まり → アプリ」。** 出すときの逆です。先にアプリだけ古くすると、
古いアプリが6文字の枝を使うのに新しい決まりが20文字を要求するので、
ライブが完全に止まります（上の「順序（守ること）」と同じ理由）。

**戻せないもの。** `ops:prune-live:run` で消した枝は戻りません。片付けの前に
中身を控えてください（スクリプトが残す JSON は件数だけです）。Firestore の
データは `npm run ops:backup` の控えから戻せます。

`scripts/stamp-live-release-day.mjs` は「最終更新から14日」を入れた回の
ためのものです。枝が変わったあとは古いライブがそもそも見えないので、
この回では要りません。

配信後、案内（チュートリアル）を一度も見ていない人には自動で案内が始まり、
その間だけ記録表が書き換わります（終了時に必ず元へ戻り、ライブ中は
始まりません）。

### 保守の道具（npm run ops:*）

本番向けの道具は `ops:` で揃えてあります。接続先は本番に決め打ちなので、
`--` で引数を渡す必要はありません。検証環境に向けたいときは
`node scripts/<名前>.mjs stg` と直に呼びます。

| 叩くもの | すること |
|---|---|
| `ops:check` | 出ている決まり・お知らせの版が手元と揃っているか |
| `ops:audit` | 本番データの粗探し（読むだけ） |
| `ops:lookup` | 逆引き表の迷子 |
| `ops:backup` | Firestore と RTDB の控えを取る |
| `ops:accept` | 配信後の受け入れ検査（先に `ops:backup` が要る） |
| `ops:orphans` | 記録の無い取り残された利用者を探す |
| `ops:reports` | 届いた不具合の便りを読む |
| `ops:prune-live` / `:run` | 古い形のライブの枝を片付ける |
| `ops:prune-reports` / `:run` | 期限の過ぎた不具合の便りを消す（月に一度） |
| `ops:expiry-rules` | 共有リンクの期限が決まりの側で効いているか（検証環境に当てる） |
| `ops:scan-japanese` | 画面に直に書かれた日本語の数（多言語化の残り） |

`ops:expiry-rules` だけは検証環境に当たります。使い捨ての枝を作り、
期限を過ぎさせて、本当に読めなくなるかを確かめて片付けます。本番のデータには
触れません。決まり（`database.rules.json`）を直したら必ず走らせてください。
画面の側の検査では、決まりが効いているかは分かりません。

`:run` の付かないほうは下見で、何も消しません。消す側だけ `:run` にして
あるので、打ち間違いで消えることはありません。

### npm run deploy:web の中身

1. `scripts/build-prod.mjs` → `expo export --platform web --clear` で `dist/` を生成し、
   焼き込まれた接続先が本番かを確かめる。そのあと `scripts/patch-index-html.mjs` が
   `lang="en"` → `"ja"` と `<title>` を直す
2. `scripts/deploy-web.ps1` → `dist/index.html` に OGP/PWA タグを注入し、`pwa/` 配下の
   manifest・Service Worker・アイコンを `dist/` へコピー
   （`dist/` は毎回再生成されるため、このコピーは毎回必要）
3. `firebase deploy --only hosting`
   直前に `firebase.json` の predeploy が `scripts/verify-hosting-bundle.mjs` を走らせ、
   `dist/` の接続先と配り先が食い違えば止める

`--clear` は必須です。付けないと、検証環境向けに書き出したときの設定が
キャッシュから使い回され、検証環境を向いた束が本番へ出ます（再現済み）。

iOS は `.github/workflows/` の EAS Build ワークフローで生成します。
ビルド前に `patch_node_modules.mjs` が CI から実行されます（`patches/` と併用）。

## ダークモード

設定 →「表示」→ 外観 で **ライト / ダーク / 端末に合わせる** を切り替えられます。
選択内容は AsyncStorage（キー `@kyudo/themeMode`）に保存されます。

### 実装方式

`src/` は復元コードでカラーリテラルが 1300 箇所以上ハードコードされており
（うち約半分は JSX 内のインライン指定）、全箇所をトークン化するのは現実的でないため、
**「ライト色 → ダーク色」を実行時に変換する**方式を採っています。変換の定義は
[src/theme.js](src/theme.js) の1ファイルに集約されています。

差し込み口は3つです。

| 差し込み口 | 対象 |
|---|---|
| [src/default_45.js](src/default_45.js) | `StyleSheet.create` の結果（styles 定義側） |
| [src/theme-runtime/jsx-runtime.js](src/theme-runtime/jsx-runtime.js) | 全 JSX の `style` / `color` 系 props（インライン側） |
| [src/default_217.js](src/default_217.js) | 色未指定の `<Text>` の既定色 |

JSX ランタイムは `babel.config.js` の `jsxImportSource: 'theme-jsx'` で全ファイルに適用され、
別名 `theme-jsx` は `metro.config.js` で `src/theme-runtime` へ解決されます。

（例: `#FFFFFF` は背景なら `#1C1C1E`、色付きボタン上の文字なら白のまま）。

### 注意点

- テーマを切り替えると **ナビゲーション配下が再マウント**されます
  （色の変換は描画時に行うため。記録データは zustand ストア側にあるので失われません）。
  タブは先頭に戻り、開いていたモーダルは閉じます。
- 変換は「対応表にある色」だけが対象です。新しい色を追加するときは
  `src/theme.js` の変換表にも追記してください。
- Web で確認したところ未変換要素は全体の 0.3% 未満（文字色は 0 件）ですが、
  ゼロではありません。気になる箇所があれば個別に対応表へ追加してください。

## ライブをリンクで配る

ライブ中の青い帯を主催者が押すと、URLを2本作れます（`src/liveShare.js`）。
団体に入っていない人にも渡せます。

| 役 | できること | 置き場所 |
|---|---|---|
| 編集用 | 記録できる。○×は全員に届く | `live_sessions/{そのライブの枝}` |
| 閲覧用 | 見るだけ | `live_view/{閲覧の枝}`（書き込み用とは別の写し） |

守りの作りは3つです。

1. **団体の合言葉は配らない。** 配ると、その1本で団体の過去も未来も全部の
   ライブに入れてしまいます。共有するライブだけを専用の枝へ移し、リンクは
   その枝だけを指します。団体の枝には、参加一覧に出すための道しるべだけが残ります。
2. **編集用と閲覧用は別々の種から作る。** 同じ種だと、閲覧リンクを持つ人が
   編集用の枝を計算できてしまいます。リンクにはその役の種しか載りません。
3. **合言葉は照合しない。枝の名前を合言葉から作る。** 画面で照らし合わせるだけだと、
   URLを持つ人は開発者ツールで素通りできます。合言葉が違えば別の枝を見にいくので、
   そこには何もありません。合言葉はURLに載りません。

総当たりは「合言葉を試す → 枝を計算 → RTDB へ問い合わせる」の繰り返しで、
律速は通信です。それでも4桁の数字なら時間をかければ開くので、合言葉には
最低の長さ（6文字）を設けてあります。画面にも「長めに」と書いてあります。

### 有効期限

配るときに持ちを選べます（3時間 / 24時間 / 7日間 / 期限なし）。既定は24時間です。
期限なしを既定にすると、ほとんどのリンクが永久に生き続けます。

期限は `live_limits/{枝}` に数（ミリ秒）で置き、**決まりの側**（`database.rules.json`）が
その枝の読み書きを丸ごと止めます。画面で「期限切れです」と出すだけでは、
開発者ツールで素通りできるためです。編集の枝と閲覧の枝の両方に置きます。
片方だけだと、もう片方から読み続けられます。

決まりでは、期限を**縮められるが延ばせない**ようにしてあります。延ばせると、
いちど配ったリンクが後からよみがえり、「期限を切った」と思っている人の
思い違いを生みます。延ばしたいときは配り直してください。二度目に配ると、
同じリンクと**最初の期限のまま**が返ります。

期限を外してよみがえらせることもできません。中身（`live_sessions` /
`live_view` / `live_history` / `live_presence`）が残っているうちは、
`live_limits` を消せない決まりにしてあります。片付けは「中身 → 期限」の順です。

決まりが効くのは**つなぎ直したとき**で、すでに開いている見張りには更新が
届き続けます。そこで盤面にも期限を載せ、画面の側からも離れるようにしてあります
（ストアの `期限で閉じるか`）。両方あって初めて「もう見えない」が成り立ちます。

手元の記録は消しません。期限が切れたのは配ったリンクであって、その人が
取った記録ではありません。

確かめ方：

```bash
npm run ops:expiry-rules
```

閲覧用は写しなので、そこへ何を書かれても記録には届きません。写しを汚されると
他の閲覧者の画面が一時的に乱れますが、次の書き込みで直ります。

### リンクで来た人（来客）に出すもの

団体に入っていない人は「来客」として扱います（ストアの `共有の来客`）。
団体のデータを何も持っていないので、出すのは**記録の画面だけ**です。

| 出すもの | 出さないもの |
|---|---|
| 記録 | 履歴・分析・設定・メンバー・出欠 |
| ライブの盤面と○× | AIチャットボット（団体の記録を見て答えるため） |
| 退出（入口の画面まで戻る） | 使い方の案内（団体の画面を順に指すため） |

人の選択も開きません。名簿を持っていないので、開いても空の一覧が出るだけです。
**団体にログイン中の人が共有リンクを開いた場合は、これまでどおり名簿から選べます。**

ログイン中に共有リンクを開くと、手元の盤面はライブの内容で上書きされます。
書きかけの記録があるときは、参加する前に知らせます（ふつうの参加と同じ扱い）。

配った先の人は、記録中の的中・氏名・立ち順を見られます。
プライバシーポリシー第16条(4)に、そのことを書いてあります。

## 多言語化（準備まで）

仕組みは `src/i18n.js`、言葉は `src/messages/` にあります。通してあるのは
読み上げの言葉（`src/a11yLabels.js`）と接続台数（`src/livePresence.js`）だけです。

画面の大半はまだ日本語が直に書かれています。その量は数えられます。

```bash
npm run ops:scan-japanese
```

2026年8月30日時点で **2,424か所・1,933種類・46ファイル**（注釈を除いた上限）。
数は変わるので、必ず上の道具で測り直してください。
だから既定は日本語のままにしてあり、言語の切り替えは画面に出していません。
いま切り替えられるようにすると、大半が日本語のまま混ざった画面になり、
日本語のままより使いにくくなります。

### 1画面ずつ移す

2,389か所を一度に移すと、差分が大きすぎて見きれません。辞書は画面・部品
ごとに分けてあり（`src/messages/a11y.js`、`src/messages/live.js` …）、
1画面ぶんの差分は次の3つだけになります。

1. その画面のファイル
2. `src/messages/<画面>.js`（新規）
3. `src/messages/index.js` の `束` に1行

手順:

1. `npm run ops:scan-japanese` で、その画面の件数を見る
2. `src/messages/<画面>.js` に `ja` と `en` を書く
3. `index.js` の `束` に足す
4. 画面の側を `訳('鍵')` に置き換える。既定は日本語なので見た目は変わらない
5. `npm test`（型検査・未定義の変数・単体）と、その画面の e2e を通す
6. 次の画面へ

移す順は **読み上げ → 記録 → 設定 → 分析** を想定しています。読み上げを
先に済ませたのは、画面の字が読めない人にとって唯一の手がかりだからです。

分け方そのものが崩れないよう、検査で押さえてあります（`test/i18n.test.js`）。

- 鍵がファイルをまたいで重なっていないこと（重なると、どちらが出るかが
  並び順で決まって追えなくなる）
- ファイルごとに `ja` と `en` が揃っていること
- `src/messages/` に置いたファイルが `束` に登録されていること
  （登録し忘れると、その画面だけ日本語のまま出る。日本語では正しく
  見えるので、英語で開くまで誰も気づかない）

### JSON ではなく .js にしている理由

この repo では「なぜそう書いたか」を注釈で残すことにしています。JSON には
注釈が書けず、「大前を訳さない理由」のような、いちばん引き継ぎたいことが
落ちます。形式より、消えないことを採りました。

「大前」「落」「立ち」は訳していません。相当する英語が無く、`archer 1` や
`last archer` と置くと意味が変わります（大前は「1番目の人」ではなく、その立ちを
起こす役）。ローマ字を残し、説明を添えてあります。剣道の `men` / `kote`、
柔道の `ippon` と同じ扱いです。

## 配信に気づかせる（web）

配信しても、**開いたままのタブは読み込み直すまで古い束のまま**動きます。
ふだんは害が小さいのですが、ライブの置き場所（枝）が変わる回では、古いままの
端末が別の枝を見て「相手の○×が出ない」という直しにくい形になります。

そこで画面の上に細い帯を出します（`src/JP_UpdateBar.js`）。押されたときだけ
読み込み直し、勝手には入れ替えません。手元の記録は端末に残るので消えません。

### 何を見て気づくか

版の番号は持ちません。`index.html` を取り直して、そこに書かれた束の名前が
いま動いている束と違えば新しい版、と判断します（`src/updateNotice.js`）。
束の名前には中身のハッシュが入るので、配信のたびに必ず変わります。
版の番号を別に置くと、置き忘れたときに黙って知らせが出なくなります。

見に行くのは、画面が戻ってきたときと30分ごと。取りに行くのは `index.html`
1枚だけです。

### キャッシュそのものは、もともと問題になっていない

「ブラウザの強いキャッシュで古い JS が残る」ことは、この構成では起きません。

| 仕組み | 何をしているか |
|---|---|
| `pwa/sw.js` | ネットワーク優先。キャッシュは通信できないときの後ろ盾だけ。`skipWaiting` と `clients.claim` で自身も即入れ替わる |
| `firebase.json` | `index.html` と `sw.js` は `no-cache`。束は名前にハッシュが入るので `immutable` |

読み込み直せば必ず新しくなります。残っていた穴は「開いたままのタブ」だけで、
そこを帯で埋めました。

## e2e の待ち方

`waitForTimeout`（決まった秒数だけ待つ）は使わない。状態か、要素の出現を待つ。

理由は速さだけではありません。**決まった秒数の待ちは、その裏にある競合を
覆い隠します。** 2026年8月30日に `e2e/live.spec.mjs` の固定待ちを外したところ、
覆われていた不具合が2つ出てきました。

| 出てきたもの | 何が起きていたか |
|---|---|
| 打ち込みが落ちる | 入力欄は controlled で、窓が開ききる前に打つと再描画で何文字か落ちる。`chk1788094022464946` が `c88094022464946` になり、**欠けた名前のライブが検証環境にでき**、参加一覧にも並んだ |
| 取り消しの確かめが早すぎる | 「3台の見え方が一致するまで」では、取り消しが届く前も一致しているので即座に返る。届いたことを確かめずに数えていた |

どちらも1500〜3000ミリ秒の待ちが覆っていて、**検査は通っていました**。

### 使う道具（`e2e/live.spec.mjs`）

| 道具 | いつ使うか |
|---|---|
| `こうなるまで待つ(読む, 良いか)` | 台をまたぐ同期。速いときは1秒足らずで届く |
| `印がつくまで待つ(page, 鍵)` | ○を入れた直後の確かめ |
| `確かに打つ(欄, 文字)` | 入力欄。打って、入ったか確かめ、違えば打ち直す |
| `画面が出るまで待つ(page)` | `goto` / `reload` のあと |
| `確かに打つ` | 入力欄。打って、入ったか確かめ、違えば打ち直す |
| `案内を止める` / `案内をあえて出す` | 開く前に案内を止める／あえて出す |
| `入り口が決まるまで待つ` | ログイン欄が出るか、もう入っているかが決まるまで |
| `ますが増えるまで待つ` / `画面が変わるまで待つ` / `横並びになるまで待つ` | 画面の変化 |

道具は `e2e/helpers.mjs` にまとめてある。各検査が同じものを別々に持っていた
ころは、今回見つけた罠（打ち込みが落ちる）の直しを1ファイルずつ入れる必要があった。

`live.spec.mjs` だけが持つもの（`射手を立てる` / `ライブを始める` /
`ライブに参加する` / `揃うまで待つ` / `印がつくまで待つ`）は、ライブ専用。

`fill()` は使わないこと。Chromium では入りますが、**WebKit では値が入りません**。

### 決まった秒数を残してよい場合

`e2e/live.spec.mjs` には4か所だけ残してあり、それぞれ理由が書いてあります。

- **「出ないこと」を見るとき** … 状態待ちにすると、出ないものを待って上限まで座る
- **外から見える合図が無いとき** … 認証の保存（IndexedDB）の書き終わりなど
- **見に行く間隔** … これは待ち時間ではない

### アプリの起動は1回にする

案内とお知らせは **開く前**に止める（`案内を止める`）。開いてから
localStorage に書いて `reload` して効かせる作りだと、1つの検査につき
アプリを2回起動することになる。

これがいちばん効いた。iPhone の `live.spec.mjs` で **17.9分 → 12.3分**。
固定待ちを減らすより大きい。ブラウザの立ち上げが重いのは WebKit ほど顕著。

案内そのものを見る検査は `案内をあえて出す` で断りを入れる。
`addInitScript` は移動のたびに走るので、断らないと検査が消した設定を
毎回もとに戻してしまう。

### 効き目

固定待ちは **182か所・363.1秒 → 77か所・123.1秒**（1機種あたり、66%減）。
起動の1回化と合わせて、全体は 34.8分 → 29.5分。

残る77か所には、消してはいけないものが含まれる（上の「決まった秒数を
残してよい場合」を参照）。数え直すには `waitForTimeout` を grep すればよい。

## 既知の課題


以前ここに挙げていた3件は解決済みです。何をどう直したかは残しておきます。
同じ形の指摘が繰り返し上がるためです。

| かつての課題 | いまの状態 |
|---|---|
| Firestore の `groups` が `auth != null` だけ | `canAccess()`（団体アカウント本人か、所属を証明した部員）に。**本番へ配信済み** |
| RTDB の `live_sessions` が認証不要 | 認証必須にしたうえで、枝を団体ごとの推測できない合言葉に変更（`src/liveSecret.js`）。**認証必須は配信済み・合言葉はまだ未配信** |
| `src/db_178.js` の `ADMIN_EMAIL` / `ADMIN_PASSWORD` | 撤去済み。本番の束にも入っていないことを確認済み |

未配信のぶんは `npm run ops:check` で確かめられます。

- **`src/` が読みにくい**: 復元コードのため minify されたまま。
  可読なソースへ戻す場合は段階的なリファクタが必要です。
- **iOSビルドに native モジュールが増えた**: `@react-native-community/netinfo` を
  正式な依存にしたことで、次回の EAS Build から NetInfo のネイティブモジュールが
  組み込まれます（Web版は `navigator.onLine` を使うため影響なし）。
