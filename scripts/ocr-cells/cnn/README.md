# 板のマスを畳み込みの網（CNN）で見分ける（2026-10-09）

アプリの板の読み取り（`src/ocr/yomu.js` の 板の印を読む）は、マスごとに ×・◎・○＼・○／ を見分ける。
2026-10-09 に、全結合の小さな網（`omomi-chiisai.json`）から、畳み込みの網（`omomi-tatami.json`・
`scripts/ocr-cells/tatami.mjs`）に替えた。重みの JSON の `形` が `'CNN'` なら yomu.js が畳み込みで読む。

## 測り方（公平な物差し）

本物の正解つきのマス 1590（写真 17 枚・板の組 10）を、**板の組を 1 つずつ外して**学習し、外した組で測る
（leave-one-board-out）。外した組は一度も学習に使っていない。学習には描いた板（26784 マス）を全部と、
外さなかった組の本物を 8 回ずつ混ぜる。

| 候補 | 外した板での当たり |
|---|---|
| A 全結合（今までの形・決まりの直しなし） | 98.2% |
| B 小さな CNN（幅 16） | 99.6〜99.75% |
| C B ＋ 形の特徴（斜めの帯・輪など 92） | 99.7〜99.8% |
| D 写真で学習済みの MobileNetV3-small（96px） | 100%（3 回とも） |
| 幅 8・12・16 の CNN、1 回読み | 99.4〜99.9%（差は数マスで、揺れの範囲） |
| D を小さな CNN に移す（蒸留）・幅 32 | 99.7% 前後（D には届かない） |
| 学習済みの小さい MobileNet（幅 0.5） | 85〜88%（だめ） |

D は 1 マス約 1000 万回の掛け算で、端末の JS では遅い（320 マスで数秒〜十数秒）。
**幅 12 ＋ 形の特徴、網 1 枚、1 回読み**を選んだ（320 マスで 0.5 秒・パソコン。重み 95KB）。
少しずらして何度も読む（ずらし）は、当たりが変わらず時間が 5 倍なので使わない。

新しい写真（10/4 の 3 枚。学習に使っていない）を端から端まで読むと（決まりの直しあり）：
今までの網 636/640 → CNN 640/640。これまでの写真ぜんぶ（Node・Chromium・WebKit の 3 通り）は落ちない。

## 学び直し方

1. 正解を足す（名前入りなので倉庫に入れない。`kyudo-ocr-ag/.hakari/seikai-*.mjs`）
2. `DUMP_HEN=32 node scripts/ocr-cells/cnn/dump.mjs 120` … アプリと同じ切り抜きでマスを書き出す（`data/`。倉庫に入れない）
3. `python scripts/ocr-cells/cnn/cmp4.py 12 3` … 板ごとに外して測る（新しい形を試すときは cmp.py の候補を足す）
4. `python scripts/ocr-cells/cnn/prod.py scripts/ocr-cells/omomi-tatami.json 12 1 1` … 本物を全部入れて学ぶ
5. `kyudo-ocr-ag/.hakari/zenbu-1009.mjs` で、これまでの写真ぜんぶを 3 通りで数え、落ちないことを見る

PyTorch（GPU）を使う。書き出しは BatchNorm を畳み込みに畳み、重みを層ごとに int8 に丸める（omomi.mjs と同じ形）。
JS と PyTorch の確からしさの差は 0.004 以内（丸めのぶん）。

## 迷ったマス

確認画面の「迷ったマス」（確からしさ 0.55 未満）は、CNN ではまれ（外した板で 1590 中 4 マス）。
全結合の網が迷っていた途中交代の段も、CNN は自信を持って正しく読む。
