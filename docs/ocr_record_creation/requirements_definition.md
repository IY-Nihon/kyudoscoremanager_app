# 画像認識による立ち順自動登録機能 要件定義書

## 1. 背景と目的
現在、弓道の練習や試合において、ホワイトボードで組まれた「立ち順（誰が何番目の立のどの的に入るか）」をアプリに手動で1人ずつ入力して記録表を作成しています。この作業には手間と時間がかかるため、ホワイトボードを撮影するだけで自動的に的確な立ち順の記録表が作成される仕組みを導入し、記録開始の効率化を図ります。

## 2. System概要
ユーザーがホワイトボードの立ち順表をカメラで撮影（または画像をアップロード）すると、システムが画像を解析します。
画像から「立（行：壱之立〜）」と「的（列：一的〜）」の位置関係およびプレートに書かれた名前を認識し、アプリ内のメンバーマッピングを行った上で、セパレータ（区切り）を挟んだ記録表データを自動生成します。

```mermaid
graph TD
    A[ホワイトボードを撮影] --> B[画像をAI解析 (Gemini等)]
    B --> C[「立」と「的」のグリッド及び名前テキストを抽出]
    C --> D[アプリ内メンバーデータベースと照合 (名寄せ)]
    D --> E[プレビュー・手動修正画面]
    E --> F[記録表の生成 (セパレータ自動挿入)]
```

## 3. 機能要件

### 3.1. 画像入力機能
- **カメラ起動・撮影**: アプリ内からカメラを起動してホワイトボードを撮影できること。
- **画像選択**: 端末のフォトライブラリから撮影済みの画像を選択してアップロードできること。
- **複数枚の追加撮影**: 立ち順が多く1枚の写真に収まらない場合、続けて写真を撮影・アップロードし、同一の記録表の末尾に解析結果を結合できること。

### 3.2. 画像解析およびレイアウト認識（AI解析）
- **グリッド構造の認識**:
  - 縦軸（壱之立、弐之立、参之立...）と横軸（一的、二的、三的、四的、落前、御落）のテーブル構造を検出する。
  - 各「立」に所属するメンバーのグループを正しく抽出する。
- **ネームプレートの文字認識 (OCR)**:
  - 各枠内にあるネームプレートに手書き・印刷された氏名をテキストとして認識する。
  - プレート内の改行文字は自動的に無視・結合して1つの名前として処理すること。
  - プレートの枠線の色（緑、黄、青、赤）や、プレートがない空欄（「選択」状態）も検知できると望ましい。
- **不要領域のフィルタリング**:
  - 立ち順表の周囲に書かれた「矢取りの図」や「メモ書き」「磁石の跡」などの不要な情報を無視し、立ち順表のグリッド領域のみを判定対象とすること。

### 3.3. メンバーマッチング（名寄せロジック）
- **データベース照合**:
  - 認識した氏名テキストを、アプリ内のメンバーデータ（`members` および `alumni`）と照合する。
  - 卒業生（Alumni）や休部中メンバーも含めて照合対象とするが、同姓による誤判定を防ぐため、現役生メンバーとのマッチング優先度を高く設定すること。
- **表記揺れの吸収**:
  - 姓名の間のスペースの有無を無視して判定する。
  - `林(飛)` や `林(真)` のように、同姓の識別子が括弧書きで付与されている場合も、登録名と部分一致またはルールベースでマッピングする。
- **未登録・ゲストの処理**:
  - メンバーデータベースに一致する名前がない場合、または「空欄」の場合は、「未選択（選択）」または「ゲスト（ホワイトボードに書かれた名前）」として仮登録する。

### 3.4. 記録表データ（Session）の自動構築
- **並び順の構成**:
  - ホワイトボード上の「的の並び（右側の一的から左側の御落）」を、アプリの記録テーブルの並び順（右から左へ一的〜御落）に正しく整列させる。
  - 各「立」の間に、自動的に「セパレータ（間隔）」を挿入する。
  - 例：`[壱之立のメンバー6人]` ➔ `[セパレータ]` ➔ `[弐之立のメンバー6人]` ... のようにデータを連結して配列を作成する。

### 3.5. 認識結果の確認・編集UI（プレビュー画面）
- **プレビュー表示**: 記録表に流し込む前に、認識された立ち順と名前の一覧を表示する。
- **手動修正**: AIの認識が間違っていたり、メンバーが見つからなかった箇所について、その場でタップしてメンバーリストから再選択、またはゲスト名を手動修正できること。

## 4. 想定事例および例外処理

### 4.1. 画像品質・撮影環境に関する例外
| No | 想定される事象（事例） | システム側の例外処理・対応案 |
| :--- | :--- | :--- |
| 1 | **手ブレ・ピンボケ・低解像度**<br>文字が潰れて認識できない。 | 「画像が不鮮明なため解析できません。再度ピントを合わせて撮影してください」と警告を表示し、再撮影を促す。 |
| 2 | **照明の反射（白飛び）・逆光**<br>ホワイトボードのテカリで一部のネームプレートの文字が読めない。 | 認識できなかったセルを**「未選択」**として処理し、プレビュー画面で該当セルを赤くハイライトしてユーザーに手動選択を促す。 |
| 3 | **斜めからの撮影（台形歪み）**<br>正面ではなく、斜め角度から撮影されたためグリッドが歪んでいる。 | AI（Gemini等）のプロンプトで「斜めからの撮影による歪みを考慮して、行と列の対応関係を論理的に解釈すること」と指示する、あるいはプレビュー前に傾き補正を行う。 |
| 4 | **ホワイトボード上の落書き・関係ないメモ**<br>ボード上の「矢取りの図」や「メモ書き」が写り込んでいる。 | 「壱之立」「一的」などのラベルで囲まれた、ネームプレートがグリッド状に並んでいる領域のみを解析対象とし、それ以外の不要な文字列・図形は無視する。 |
| 5 | **立ち順が多く、1枚の写真に収まらない**<br>「八之立」以降もあり、1枚の写真では文字が小さくなりすぎる。 | 「写真を続けて追加する」機能をサポートし、2枚目以降の写真を撮影・アップロードして同一の記録表の末尾に解析結果を結合できるようにする。 |

### 4.2. メンバーマッチングに関する例外
| No | 想定される事象（事例） | システム側の例外処理・対応案 |
| :--- | :--- | :--- |
| 6 | **同姓同名のメンバーが存在する**<br>ホワイトボード上の名前が、アプリ内の複数人と一致する。 | プレビュー画面で「同姓同名の候補が複数あります」と提示し、ユーザーにタップさせて正しい方を特定させる。 |
| 7 | **同姓メンバーの表記の曖昧性**<br>ボードには `林` とだけあるが、アプリには `林(飛)` と `林(真)` がいる。 | 完全一致しないため「警告（要確認マーク）」を出し、プレビュー画面でどちらの「林」かを選択させる。 |
| 8 | **手書きによる漢字の間違い・略字**<br>`渡辺` が `渡邊` と書かれている、あるいは一部の文字が誤認識された。 | 氏名テキストの編集距離や文字類似度を計算し、最も近い登録メンバーを「候補」として自動で仮当てする。 |
| 9 | **部外者（ゲスト）のプレート**<br>メンバーデータベースに登録のない名前。 | 自動的に**「ゲスト」**として扱い、認識したテキストをそのまま射手名にセットして登録する。 |
| 10| **文字数が多い名前や改行**<br>外国人メンバーなどで名前が長く、プレート内で2行に改行されて手書きされている。 | 同一のプレート枠内（グリッドの1セル内）にある改行文字は無視し、1つの文字列として結合した上でマッチングを行う。 |
| 11| **卒業生や休部メンバーの急な参加**<br>非表示にしている卒業生などが急遽立ちに入り、ボードにプレートが貼られた。 | 照合対象に卒業生リストも含めて検索する。ただし、同姓による誤判定防止のため、現役生メンバーとのマッチング優先度を高く設定する。 |

### 4.3. ホワイトボードの運用・レイアウトに関する例外
| No | 想定される事象（事例） | システム側の例外処理・対応案 |
| :--- | :--- | :--- |
| 12| **立ちの途中でメンバーが抜けている（空き的）**<br>例：弐之立の二的だけプレートがなく空欄（「選択」状態）。 | 空欄部分を飛ばして順序を詰めるのではなく、**「未選択」の空のセル**としてそのまま残し、的順（一的・二的・三的...）のズレを防ぐ。 |
| 13| **立ごとに人数が異なる（変則的な立ち順）**<br>例：1立が5人のところと、6人のところが混在している。 | グリッド内のネームプレートの有無をセルごとに正しく判定し、登録されている射手のみをそれぞれの立に割り当てる。 |
| 14| **ホワイトボードのレイアウト変更**<br>縦軸と横軸が入れ替わったり、フォーマットが変わった。 | 設定画面に「ホワイトボードの向き（通常：行＝立、列＝的 / 反転：行＝的、列＝立）」を選択できるオプションを用意する。 |

### 4.4. システム・通信に関する例外
| No | 想定される事象（事例） | システム側の例外処理・対応案 |
| :--- | :--- | :--- |
| 15| **通信オフライン状態**<br>道場内など電波の届かない場所で解析を実行した。 | ローカルで検知し、「オフラインのため画像解析ができません。電波の良い場所で試すか、手動で登録してください」と案内する。 |
| 16| **AI APIのタイムアウト・エラー**<br>サーバー混雑等で解析が途中で失敗した。 | 一定時間でタイムアウト処理を行い、エラーメッセージと共に、元の画像を画面の片隅に表示しながら「手動で入力する」ための補助画面へ遷移させる。 |

## 5. 技術アプローチ（実装イメージ）
本アプリは React Native / Expo Web で構築されているため、以下の構成が考えられます。

- **フロントエンド（アプリ側）**:
  - `expo-image-picker` などを用いた画像の撮影・選択UI。
  - 画像データ（Base64形式など）をバックエンドまたは直接 API へ送信する仕組み。
  - 認識したデータをグリッド状に並べ替えて修正できるプレビュー画面（React Nativeコンポーネント）。
- **バックエンド / AI解析側 (Gemini API 等)**:
  - 送信された画像と、アプリ内の「現在の登録メンバー名リスト」をまとめて Gemini API などのマルチモーダルAIに渡し、画像とテキストリストの照合（名寄せ）を依頼する。
  - AIからは構造化されたJSON（例: `[ { "tachi": 1, "archers": ["真玉", "上西", "渡辺", "小堀", "瀧", "橋本"] }, ... ]`）を受け取り、フロントエンドでパースして記録表データ（Session）を生成する。
