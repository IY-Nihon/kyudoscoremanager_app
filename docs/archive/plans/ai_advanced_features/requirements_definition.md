# 弓道スコアマネージャー AI拡張機能 要件定義書

## 1. プロジェクトの目的と背景
現在のAIアシスタント（AIChatBot）は「内部データの読み取りと回答」にとどまっています。本プロジェクトでは、AIに「外部情報の検索（Google Search Grounding）」「画面操作（ナビゲーション）」「データの追加・編集」の3つの拡張機能を持たせることで、ユーザー体験（UX）を劇的に向上させ、弓道部のIT化を強力にサポートする次世代のエージェントへと進化させます。

## 2. スコープ（対象範囲）
- **対象プラットフォーム**: React Native (Web / Expo)
- **対象AIモデル**: Gemini API (`gemini-1.5-flash` またはそれ以降のモデル)
- **対象機能**: `JP_AIChatBot_1034.js` および関連する状態管理（Zustand）、ルーティング設定。

---

## 3. 機能要件 (Functional Requirements)

### 3.1 Google Search Grounding（外部知識の取得）
* **機能概要**: AIが事前学習していない情報（弓道連盟の最新ルール、他校の事例、用具の価格など）を問われた際、自動的にGoogle検索を実行して回答する。
* **動作仕様**:
  * トグルスイッチ等のON/OFF設定は設けず、**常時有効（デフォルト機能）**として実装する。
  * 検索を利用して回答した場合は、回答の末尾または関連箇所に情報元（ソースURLや引用元）を併記し、情報の信頼性を担保する。
  * アプリ内のデータ（部員の成績など）を問われた場合は、Web検索よりも内部データを優先するようシステムプロンプトで制御する。

### 3.2 アプリ自動操作（ナビゲーション連携）
* **機能概要**: ユーザーの自然言語による指示に基づいて、対象の画面へ自動的に遷移する。
* **動作仕様**:
  * AIチャットボットからReact Navigationの `navigate` を呼び出せるように、グローバルなNavigationRefを設定する。
  * **対応アクション例**:
    * 「〇〇の分析画面を開いて」 → 対象部員の分析タブへ遷移
    * 「設定画面を開いて」 → 設定タブへ遷移
    * 「メンバーを追加したい」 → メンバー追加画面（またはモーダル）を展開
  * 遷移完了後、AIから「〇〇の画面を開きました」とテキストでフィードバックを行う。

### 3.3 データ自動入力・編集（データベース連携）
* **機能概要**: AIへの指示により、直接Zustandストア（および同期先のFirebase）のデータを追加・更新・削除する。
* **動作仕様**:
  * Function Callingにおいて、`addMember`, `updateMemberGrade`, `deleteSession` などの破壊的変更を伴う関数を定義する。
  * **対応アクション例**:
    * 新入部員の登録（名前、学年、性別を推論して入力）
    * 進級処理（一括で全メンバーの学年をインクリメント）
  * **必須の安全対策（Human-in-the-loop）**:
    * データの追加・変更・削除が提案された場合、**即座に実行しない**。
    * チャット画面内に「以下の内容で登録しますか？ [承認] / [キャンセル]」の専用UIコンポーネント（アクションカード）を表示する。
    * ユーザーが [承認] をタップした時点で初めてストアへの書き込み処理を実行する。

---

## 4. 非機能要件 (Non-Functional Requirements)

* **UI/UXと安全性**:
  * AIの誤認識によるデータ破壊を防ぐため、破壊的変更には必ずユーザーの最終承認（アクションカード）を必須とする。
  * 実行中の待機状態（ローディング）を視覚的に分かりやすく表示する。
* **パフォーマンス（速度）**:
  * Google Search Groundingを使用することでレスポンスが通常より数秒遅れることを前提とし、チャットUI側で「検索中...」や「情報収集中...」といったユーザーにストレスを与えないインジケーターを実装する。
* **APIコストと利用制限**:
  * Google Search GroundingはAPIリクエストごとに少額の課金が発生する可能性がある（または無料枠の利用制限に影響する）。システムプロンプトの文字数を最適化し、無駄なトークン消費を抑える。

## 5. フェーズ別 実装計画 (Implementation Plan)

### Phase 1: 基盤構築とGoogle Search Groundingの導入
* Gemini APIのリクエストパラメータに `googleSearchRetrieval` を追加。
* システムプロンプトを改修し、外部知識と内部データの使い分けを定義。
* （※トグルスイッチなしで常時ONとしてリリース）

### Phase 2: ナビゲーション連携の実装
* ルート階層（App.js または Navigator）に `NavigationContainer` の Ref を持たせる。
* AIChatBotに画面遷移用の Function Calling ツールを追加。
* チャットを開いたまま背景の画面が切り替わるUI挙動のテスト。

### Phase 3: データ連携と承認UI（アクションカード）の実装
* チャットバブル内にレンダリングできるカスタムUI（承認/キャンセルボタン）を構築。
* Zustandストアの各種Action（追加・編集・削除）をFunction Callingツールとして定義。
* ユーザーが承認ボタンを押した際のコールバック処理の実装。
