# 卒業生（grade: 5）導入の実装計画 (Implementation Plan)

## 目的
4年生が卒業した際にデータが物理削除（alumniへ移動）される従来の仕様を廃止し、`members` コレクション内で `grade: 5` として保持することで、過去の出欠データや的中記録との整合性を維持し、継続的な分析を可能にする。

## 変更内容

### 1. データストア (`JP_useScoreStore_174.js`)
- **進級ロジックの修正**: 4年生を削除せず、`grade: 5` に更新する。
- **データ取得の統合**: `members` と `alumni` の両方を state として保持し、UI側で統合して扱えるようにする。

### 2. メンバー管理画面 (`JP_MemberScreen_1022.js`)
- **学年選択の拡張**: ステッパーの範囲を1〜5に変更。
- **表示ロジック**: 5年生を「卒業生」としてラベリングし、期の計算を自動化する。

### 3. 的中記録画面 (`JP_ArcherActionModal_689.js`)
- **メンバーリストの分離**: 1-4年生を「現役生」、5年生以上を「卒業生」としてリストを分けて表示。
- **互換性維持**: 旧卒業生データ（alumni）も「卒業生」セクションに統合表示。

### 4. 出欠管理 (`JP_EditSessionModal_694.js`)
- **データマージ**: 過去の記録編集時に、全メンバー（5年生含む）と旧卒業生を表示。
- **ソート順**: 学年（1→2→3→4→5）に基づいた並び替え。

### 5. 分析画面 (`JP_AnalysisScreen_1000.js`)
- **フィルタ拡張**: 学年フィルタに「卒業生」を追加。
- **集計ロジック**: 5年生と旧卒業生を合算して分析対象にする。

## 検証計画
- 進級処理のシミュレーション（Firestoreのデータ確認）。
- 各画面での5年生の表示確認。
- 検索・フィルタ機能の動作確認。
